## 已确认问题：按优先级处理

P1 指高优先级的科学结果错误或输入隔离失效；P2 指特定流程下的数据安全、可靠性或语义缺口。没有发现并确认必须按 P0 处置的问题。

### A1 · P1 · 默认周期成键可能静默漏键

证据：`src/renderer/CrystalScene.ts:738–813`。默认模式只考虑 ±1 镜像并裁剪到分数坐标 `[-0.08, 1.08]`，还以 `c > 1.3 × max(a,b)` 自动把 z 方向镜像禁掉。

复现：5 Å 立方晶胞中两个 C 位于 `(0.15,0.5,0.5)`、`(0.85,0.5,0.5)`，跨边界距离 1.5 Å，落在当前默认成键阈值内。默认只产生 2 个显示原子，启用由相同半径生成的显式规则则产生 4 个。另一个 5×5×10 Å 的合成晶胞，z=0.03/0.97 的跨边界近邻也被长轴启发式遗漏。

支持方：面边缘补全与 slab 推断能减少画面拥挤。反方：晶胞长轴不能证明该方向非周期，固定分数宽度不能代表物理截断距离。建议：默认与规则模式复用倒格矢界限搜索；逐轴周期性由数据或用户明确指定。验收应比较两条路径的邻接图，并覆盖斜晶胞、长轴体相、小晶胞和展开坐标。

### A2 · P1 · 晶胞换基后弛豫约束的物理方向改变

证据：`src/utils/unitCellTransform.ts:115` 复制原子元数据时原样保留 `selectiveDynamics`。

复现：输入 `F T T`，交换 a/b 基矢后仍输出 `F T T`。若保持原物理约束，应为 `T F T`。VASP 明确规定这些标记作用于 Direct 坐标方向，不受输入坐标模式影响，见 [VASP POSCAR 官方说明](https://vasp.at/wiki/index.php/POSCAR)。

支持方：保留元数据通常比丢弃好。反方：换基后“原样保留”会改变含义，且错误可直接流入后续计算。建议：置换基底时同步映射标记；一般剪切/混合变换若不能用三个布尔值表达原约束，应明确拒绝或要求重新定义，不静默转换。

### A3 · P1 · 项目 JSON 的原子字段校验不完整

证据：`src/project.ts:32–40`、`src/utils/validation.ts:75–90`。已检查坐标、占据率、颜色、半径和位移，但未完整验证 `name`、`selectiveDynamics`、派生身份字段等。

复现一：`atom.name={unexpected:'object'}` 通过 `parseProject`，实际原子表组件渲染抛出“Objects are not valid as a React child”。复现二：`selectiveDynamics=['false',false,false]` 通过导入并导出为 `T F F`，字符串被按真值处理。

支持方：已有版本、大小、原型危险键和多层参数检查。反方：Worker 解析成功后即替换当前状态，漏检字段随后进入 React 与科学导出。建议：对完整项目结构执行运行时 schema 校验，只构造受支持字段；校验枚举、字符串长度、布尔元组、引用与字段组合，禁止外部文件伪造内部周期镜像身份。这里确认的是可用性和数据完整性问题，未证实脚本执行或数据外传。

### A4 · P2 · 属性窗取消不能撤销尚未完成的异步导入

证据：`src/components/VestaPropertiesModal.ts:400–404`、`src/App.tsx:254–266,647`。Cancel 恢复快照并关闭窗口，但不取消 Worker、不更新导入代次。

浏览器复现：属性窗内导入 CHGCAR，将 Worker 发送人为延后 1.5 秒，在结果返回前点击 Cancel；先看到空白恢复，随后文件仍载入并替换工作区。

支持方：同步编辑及已经完成的导入回滚有测试。反方：用户已经取消的事务仍能提交结果。建议：让导入任务归属属性事务，取消时终止任务并失效代次；覆盖 Cancel、Escape、关闭窗口、导入失败与关闭后重开。

### A5 · P2 · 合法的大项目可能完全没有撤销能力

证据：`src/project.ts:99–110`。每个历史节点完整序列化结构与体数据，历史限额按字符串长度乘二估算 24 MiB，文件限额则为 24 MiB UTF-8。

复现：四通道 64³ 合成网格项目为 20,973,153 字节，可以保存。仅切换一次轮廓，上一状态就被预算清掉，`undo()` 返回 null。当前状态和 redo 的内存也未纳入同一完整预算；这是另一个需要核定的预算边界。

支持方：丢弃旧历史可避免持续增长。反方：支持导入的数据范围与撤销承诺不一致，样式修改重复存储不可变大网格。建议：网格按内容引用，历史保存操作差异或结构共享；至少明确提示撤销不可用，并测量大数据下开属性窗、拖滑块、保存的主线程耗时。

### A6 · P2 · 化学式忽略部分占据率

证据：`src/components/VestaBottomPanel.tsx:35–41`，每条原子记录累加 1。

复现：两个占据率均为 0.5 的 C 位点显示 `Formula: C2`，占据率加权的晶胞总量实际为 C1。

支持方：它准确统计了记录条数。反方：标注为 Formula 时读者会把它当作化学组成，尤其不利于无序与掺杂结构。建议：分开显示位点数、加权晶胞组成和约化化学式；对占据率总和、互斥无序位点保留说明。

### A7 · P2 · 周期补全合并了不同来源的重合位点

证据：`src/utils/bonding.ts:97–98,119`，镜像去重键仅含元素与舍入坐标，不含来源位点 ID。

复现：同一坐标有两个独立 C 位点 `C_A`、`C_B`，各占据 0.5；跨边界补全只留下 `C_A` 的镜像。源结构未被删除，但显示位点、按标签匹配和配位结果可能不完整。

支持方：几何去重可以减少重叠图元。反方：不同无序位点不是同一个科学对象，显示优化不能决定数据身份。建议：使用来源位点 ID 加整数平移作为身份；任何视觉合并都保留独立语义和选择映射。

### A8 · P2 · Extended XYZ 被无提示地当作非周期 XYZ

证据：`src/parsers/xyz.ts:21–48`。注释行全部作为标题，额外属性列被忽略，周期标记固定 false。

复现：带 `Lattice="5 0 0 0 5 0 0 0 5" Properties=species:S:1:pos:R:3 pbc="T T T"` 的单帧文件正常导入，却没有晶格且 `isPeriodic=false`。这些字段属于扩展格式元数据，见 [libAtoms Extended XYZ 规范](https://github.com/libAtoms/extxyz)。

支持方：当前只承诺基本 XYZ，完整支持扩展格式工作量较大。反方：同样的扩展名和“导入成功”让用户无法知道周期信息被丢弃。建议：先识别并明确拒绝/说明损失，再根据需求支持 `Lattice/Properties/pbc`，不能只在说明文档里写限制。

### A9 · P2 · 多标签页共用唯一恢复槽

证据：`src/projectStorage.ts:1–25`，所有工作区写同一个数据库的 `latest`。

浏览器复现：同时打开 A/B 空白页；A 导入并自动保存项目 A，B 再保存项目 B；刷新 A 并恢复，拿到的是 B。A 未关闭前内存中的模型仍在，但其恢复副本已被替换。

支持方：单工作区恢复实现简洁，且不是多项目库。反方：两个标签页是正常使用方式，界面均显示“已自动保存到本机”，但每页没有独立恢复保证。建议：工作区 ID、版本/写入者标记和恢复列表；增加跨标签冲突提示，覆盖配额耗尽、事务中止及刷新时间窗口。

## 已知但尚未正面解决的难题

不能从代码推断“故意逃避”。更准确的是，以下复杂度仍由简化模型承担：

1. **统一科学身份。** 基胞位点、对称等价点、周期镜像、重合无序位点和超胞副本缺少统一且稳定的身份契约；坐标相同不能等同于位点相同。
2. **变换下的元数据语义。** 保留字段不等于保留物理含义。弛豫约束已复现错误；后续应同样审查原胞归约对不同位移张量、标量及标签的处理。
3. **资源上限与交互承诺的协调。** 文件可读、场景可画、项目可存、历史可回退是四件事。Worker 不会自动解决主线程历史序列化、快照复制与网格传递成本。
4. **可视化与物理解释的界线。** `renderHBonds()` 以 H–受体距离 1.5–3.1 Å 生成连线，没有核验供体成键和角度，还混入金属弱相互作用；这些应称为几何候选并提供判据，不能让样式承担化学结论。
5. **异常恢复的事务一致性。** 文件 Worker、属性快照、历史、IndexedDB 和渲染状态各自有保护，但取消和多标签复现表明它们尚未形成一个完整事务边界。

## 安全与稳固：尚待加固或补证

- **完整输入边界：** 优先修复 A3，对深度、字符串/数组长度、语义字段和引用一致性做系统验证；加入畸形项目/CIF/体数据生成与差异测试。
- **数据恢复：** 修复 A4/A5/A9；在关闭/刷新时处理尚未持久化状态，验证存储禁用、QuotaExceeded、事务 abort。700 ms 防抖不是关闭前保存保证。
- **发布身份：** `tests/deployment/https.spec.ts:13` 只要求版本字符串形如版本号，资源哈希取自线上自己的清单，没有核对预期 commit。旧部署及其自洽清单也可能通过；应从部署任务传入预期 SHA 并比较。
- **发布失败处置：** Pages 的验收在部署之后执行，工作流没有失败后自动恢复既有已知良好产物；当前回滚要重新构建并通过最新审计，历史依赖出现漏洞可能阻塞紧急恢复。需要真实演练并保存经过验收的不可变产物。
- **供应链与纵深防护：** Actions 使用版本标签而非完整提交 SHA；源码 `index.html` 未定义 CSP。本次未检查线上响应头或账户/分支权限，不能据此宣称线上完全没有 CSP，也没有证据宣称供应链已经被入侵。应在发布验收中补上相应检查。
- **设备覆盖：** 当前 Playwright 配置使用单一 Chromium/Edge 软件图形路径。Safari/Firefox、移动真机、长时间反复导入/导出、GPU context loss、内存回落和实际 8K 峰值仍需单独验收；窄屏测试不等于移动设备验证。
